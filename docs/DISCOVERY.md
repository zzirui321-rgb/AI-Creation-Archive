# 仓库发现与模块绑定

发现用于适配实际工程，不用于重排工程目录。唯一稳定入口是公共规范及其清单链接。其余资料由 resources 的逻辑名称定位；业务代码由 bindings 定位。

## 发现依据

优先读取现有 workspace/模块清单、构建声明、导出接口、服务注册、依赖方向和已接受架构决策，再抽查实现与测试确认。名称匹配只是候选线索。遵守环境和资料访问授权，不扫描仓库外的私有会话或全盘文件。

候选绑定记录 resource_id、module_id、当前 checkout 内相对位置、文件/目录/符号类型、定位证据和发现 commit。默认 proposed；相关 Owner 确认后才 accepted。歧义写出候选与证据，只阻塞受影响模块，不要求所有人反复解释整个项目。

## 路径的地位

路径是当前仓库的定位数据，不是职责定义或程序常量。只在一个绑定中维护位置，任务引用 resource_id；代码移动后更新这一绑定。不得复制具体位置到每位 Agent 的独立提示词中。

资源可以是一组文件、一个导出符号或子模块。按物理位置嵌套时，采用已确认的最具体资源归属；不能把父目录范围解释为可写所有子模块。符号/文件边界无法机械判断时拆分成明确资源或要求接口 Owner 评审。

## 每次启动重新核对

确认当前根目录和 checkout；确认 accepted 资源仍存在且导出/依赖证据相符；检查重命名、资源 hash 或相关提交变化。发现偏差先标 stale，重新提出绑定，不能沿旧路径创建一套重复文件。

清单的 discovery_commit 是定位依据，不要求每次无关提交都重绑。只在实际位置、接口或归属证据变化时更新。任务的分支与被验证 commit 仍需核实。

## 写入前置条件

任务涉及模块的资源已 accepted；任务归属已由主干接受；依赖与契约满足；现有环境已定位；所有目标写入都可解析到任务允许资源。缺任何一项，就保存明确缺口而不猜测。

初次导入模板可先创建未绑定的 planned 任务。待绑定和验证命令可用后转 ready；不是把所有待办直接宣称为可执行任务。
