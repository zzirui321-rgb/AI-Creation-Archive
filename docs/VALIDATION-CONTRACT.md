# 接入既有 CI 的检查契约

此文件定义检查输入与失败条件，未提供或启用工作流。团队使用现有工具链实现，不为协作规范安装另一套环境。

当前 command_ref collaboration-validation 仅实现 JSON Schema、资源/命令/任务引用及依赖 DAG 检查。下列 PR 范围、认领历史、评审真实性和权限检查是待接入契约，不是本地脚本已有能力。T011 的明确 bootstrap 授权见 migration-decision，不推广为后续任务豁免。

输入：PR base/head、当前清单、已接受绑定、任务记录、既有环境约束、命令引用及实际结果。

必须失败的情况：

1. 实际写入资源未绑定、绑定 stale/proposed，或不属于任务范围及负责角色。
2. 父模块任务修改另一角色已独立绑定的子资源。
3. 修改环境 protected_resource_ids 对应资源，或试图在同一实现 PR 取消保护。
4. 认领尚未被主干接受就提交实现；出现重叠活跃写范围；重写 history 或未经记录转移会话。
5. 实现 PR 扩大任务范围、降低验收/检查条件、修改绑定扩权。
6. 依赖未完成、状态迁移无效、缺真实验证证据、命令未接入却声称已验证。
7. 使用本机绝对位置作为运行配置，或将临时本机产物作为唯一交接引用。

范围与检查标准从 PR base 的已接受数据解析，不能以 head 中自行放宽的配置为准。单纯认领/交接的元数据 PR 不宣称业务完成，不要求执行不存在的业务命令；仍验证结构、状态和并发约束。

Schema 可用团队现有 JSON Schema 校验能力检查；它只验证基本结构。归属、状态、权限、证据真实性和主干最新要求仍需上述 CI/评审/仓库设置共同落实。当前模板未宣称这些远端保障已经开启。
