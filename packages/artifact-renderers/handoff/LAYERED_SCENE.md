# Independent Layers And Exact Pixel Reuse

## Contract

Pixel preservation is implemented by deterministic composition, not by asking
a diffusion model to reproduce an unchanged background. Declare independent
image nodes with `execution.params.layer_role`:

- `background`: empty scene/environment plate. Bind only environment/style inputs.
- `subject`: isolated subject on neutral background, extracted to RGBA. Bind only subject/style inputs.
- `detail`: independent additive prop/effect, extracted to RGBA. Bind only its detail/style inputs.
- `scene` or omitted: legacy full image generation. It does not infer a semantic edit mask from a free-form prompt.

The same design works for objects, product mockups, diagrams, people and other
subjects. These roles have no fixed character, setting or panel count.
Empty detail produces a fully transparent local materialized PNG and makes no
model call. A nonempty layer retains its actual Live API/Local Fallback source.

The model receives an isolation instruction for subject/detail, or empty-scene
instruction for background. PNG alpha is retained. Opaque outputs use corner
color estimation, connected edge flood-fill and Gaussian feathering. Ambiguous
extraction fails or uses explicitly enabled fallback; it is not called perfect
semantic segmentation. A supplied alpha PNG or explicit mask is preferable for
complex hair, transparent materials or nonuniform source backgrounds.

## Composition

Use the existing `layout_compose` adapter:

```json
{
  "layout": {
    "mode": "layer_stack",
    "base_input": "background",
    "layers": [
      {"input": "subject", "role": "subject", "rect": [0.27, 0.16, 0.46, 0.80]},
      {"input": "detail", "role": "detail", "rect": [0.76, 0.08, 0.20, 0.26]}
    ]
  }
}
```

Input port values resolve to standard A Artifact IDs. Rectangles are normalized
`[x, y, width, height]`, bounded to the base canvas. Overlay alpha bounds are
cropped by default, fitted with preserved aspect ratio, and placed in that region.
`crop: false` keeps the original overlay canvas. Layer order is array order.
Optional `inputs.bubbles` is an array of `{text, rect}` and draws on a separate
overlay; changing a bubble cannot change pixels outside its own support.

The base image is decoded at its original dimensions and never resized, filtered
or regenerated by the composer. Outside the union of overlay alpha support,
the result preserves the exact decoded base pixels. Replacing a subject preserves
Original/Fork pixels outside the union of old and new subject masks. Pixels
newly covered or uncovered by a changed silhouette are deliberately editable.
The cached original background file/hash remains unchanged.

Changing background reuses foreground PNGs and placement. Fully opaque
foreground pixels stay identical; feathered/translucent edge pixels appropriately
blend against the new background. Claiming identical blended edge pixels while
changing the background would be incorrect.

Every independently appendable element should have its own detail layer/node.
Append into a previously empty detail variable adds that layer without rerendering
subject or background. Appending more text to an already populated single detail
node revises that node as a whole; retaining every previous prop requires
separate detail layers. The engine does not invent a DAG from arbitrary prose.

The old grid/vertical/horizontal composer remains. Each panel can first be a
layer_stack node; its standard output is then an input to the outer comic grid.
The field-guide acceptance configuration now uses same-canvas background/subject
fusion instead of two juxtaposed images. Old imported revisions remain immutable;
import the new configuration to use its new dependency boundaries.

## Explicit Masked Replacement

For a layout use `layout.mode: "masked_replace"`, an overlay with `crop: false`
and `mask_input` naming a grayscale mask Artifact. Mask dimensions must exactly
match the base; no silent mask resize. White means replace, black means protect.
Both alpha and explicit mask are multiplied before blending.

An `image_gen` node can also set `params.edit_mode: "masked_replace"` and provide
`inputs.original_image` and `inputs.edit_mask` as image Artifacts. After model
generation, B applies the mask locally. Original, mask and candidate must share
dimensions. This guarantees protected pixels even if the model changed them.
It does not recover background hidden behind an old object; use a clean background
plate when replacing silhouettes. No claim is made that the local model has a
native inpainting endpoint.

## Runtime And Artifacts

D calculates dirty propagation and reads cached background/subject/detail
Artifacts. B consumes the resolved references and records a real PNG with SHA256,
base identity, layer regions/roles, effective mask hash and protected pixel count.
The front-end renderer supports full composition and individual layer inspection,
including each layer's true generation source and cache decision.

Image adapter version 6, composition adapter version 3, and bridge cache identities
invalidate results generated under the previous full-image interpretation.
No shared A Schema change is required; metadata uses the existing preview sidecar.

## Reproduce Acceptance

Generate labelled synthetic input files:

```sh
python -m preview.scripts.layered_cases --output packages/artifact-renderers/demo/generated/layered
```

`layered-scene.aica.json` uses four independent nodes; `layered-comic.aica.json`
uses shared image layers, two composed panels, then an outer comic layout.

```sh
node packages/artifact-renderers/scripts/verify-layered-runtime.mjs <site-origin> <image-endpoint> <model-id> <existing-python>
```

The browser runner registers a synthetic platform account and exercises actual
Fork/Run/Artifact APIs. It checks both stages, subject Override, detail Append,
environment Override, and repeated cache hits. Its independent pixel checker
reads actual output/foreground PNGs and proves protected-region max error is zero.
Screenshots, raw PNGs, masks and reports stay in the ignored `.c-integration/layered/`
directory, not in Git. No API key or session token is stored in the report.
