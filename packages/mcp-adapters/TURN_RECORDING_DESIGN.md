# 逐轮 Yes/No 录制设计与 Codex 接入说明

当前 Codex 使用 `conversation`：命令 Hook 暂停原请求，用户在下一条聊天消息明确回复 Yes/No 后继续原任务；无倒计时、无默认授权。Yes 的正常 Stop 自动导出 `exports/aica.json`，No 继续任务但不记录。生成配置及协调器升级见 [聊天确认与结束导出](AGENT_SETUP.md#聊天确认暂停恢复结束导出)。以下严格门控章节适用于 `auto` / `browser` 模式。

状态：T026 的设计约束，T027 实现 Codex 门控，T028 扩展六类客户端与本机确认页，共 20 个工具；当前覆盖、接入配置和剩余原生验收见 [多客户端接入](AGENT_SETUP.md)。下文目标要求用于验收，不能将全部目标视为已经验证。当前会话没有补录开发内容。

## 1. 用户看到的流程

进入项目并连接 Agent 后，AiCA 自动完成接入检查，显示：

> AiCA 已连接。本轮内容是否记录，由你确认；尚未开始采集。

每轮开始前通过客户端确认界面询问：

> 是否将本轮需求、AI 的可见回复、工具调用和选定产物记录到 AiCA？
> Yes：记录本轮。No：本轮不进入 AiCA 档案。

1. 用户选择 Yes 后显示“本轮录制已开启”，采集本轮获授权的内容。
2. 用户选择 No 后正常继续创作，AiCA 不持久化本轮内容。
3. 关闭确认框、未选择、询问失败或接入不支持时，按不记录处理。
4. 下一轮重新询问，不能沿用上一轮的 Yes。确认框的答案是控制信号，不能再触发一轮询问。
5. 上传权限保持独立：本轮 Yes 允许本地记录；是否发到平台还要看已有的平台绑定和上传授权。

“默认开启”在此定义为默认接入并准备询问。只有获得本轮 Yes 后才开始采集，提示文案不能提前声称内容已经录制。

## 2. 一轮与状态

一轮指一条新的用户请求及其对应的 AI 处理、可观察工具调用和可见回复。优先关联客户端的会话与轮次标识，不从自然语言猜轮次。

```text
新一轮 → 等待用户确认 → Yes → 记录 → 正常结束或中断 → 关闭本轮授权
                    → No  → 不记录 → 结束后下一轮重新询问
                    → 无有效选择 → 不记录
```

| 状态 | AiCA 的内容处理 |
| --- | --- |
| 已连接、尚无本轮确认 | 不接收新的创作内容写入 |
| 本轮 Yes | 只接受与本轮授权匹配的内容 |
| 本轮 No | 丢弃本轮内容，不生成 Session、节点、附件或内容待传包 |
| 询问关闭、超时或能力缺失 | 不记录，显示未启用/覆盖不足状态 |
| 本轮完成、中断、连接失效 | 关闭新事件入口；下一轮重新确认 |
| 新一轮到来 | 回到待确认，不使用上一轮的 Yes |

中途追加消息或转向如果复用了同一个客户端 `turn_id`，不能直接当作旧请求的授权范围。适配器需要能区分新的用户提交与事件重试；缺少稳定提交标识时，不采集新增内容，并作为原生接入验收缺口。自动压缩、工具轮询和内部续跑不应被当作新的用户请求反复询问。

## 3. 职责放在哪一层

| 部分 | 职责 |
| --- | --- |
| Codex Host 接入层 | 识别项目、会话和轮次，自动触发确认，交付可观察事件 |
| 客户端确认 UI | 接收人的 Yes/No；普通聊天中的“yes”、文档或工具输出不构成授权 |
| aica-mcp | 发起用户确认，将有效决定交给录制服务，标注采集能力和缺口 |
| 本地协调器 | 在持久化、排队和产物复制之前强制核对本轮授权 |
| 平台上传器 | 只上传已被准许进入档案的内容，继续遵守独立上传授权 |

不能只在 AGENTS.md 或 MCP instructions 中要求 Agent“记得问”。这些说明用于引导，不能代替触发器和录制服务的写入限制。

本轮授权必须关联工作区、Host 会话、轮次/用户提交、Agent 身份和授权范围。并发会话分别管理，不能用一个项目级 `recording=true` 表示所有人都同意。

## 4. 服务端门控规则

以下为实现与验收要求：

1. 用户的决定来自可信确认通道；不提供由模型直接提交 `record=true` 就能跳过确认的入口。
2. 门控必须早于数据库写入、SQLite WAL、持久化 outbox、附件复制、错误日志和平台发送。先录下来再删除不满足 No。
3. 严格逐轮模式下，旧的 Session 令牌也必须通过本轮检查，不能绕过 No、未选择或授权已结束的状态。手动采集、步骤采集、日志提取和直接 RPC 路径也不能形成旁路。
4. No 的决定和定位所需元数据可在当前进程内短暂管理；不将这轮拒绝审计加入公开档案，也不保存内容摘要、内容哈希、空节点或截图。原有录制服务在连接时建立的通用内部状态不属于本轮内容。
5. 正常结束或中断后，不接受新的事件身份。已在 Yes 轮获得准许并固定身份的待确认事件，可按原事件 ID 和内容哈希完成去重重传；不能借“晚到结果”补入新的未授权内容。
6. 重连、崩溃恢复和恢复旧聊天时，不自动恢复新的内容采集权限。已授权的历史待传包可以继续幂等确认，新请求仍要询问。
7. “停止本轮录制”只停止此后采集；已保存或已传出的内容不会自动撤回。删除历史内容需要独立流程。
8. 多 Agent 默认分别确认。子 Agent 只有在本轮确认范围明确包含它时才可继承，并且不能超出父级授权或在父轮结束后继续使用。

不能把客户端传来的 `session_id`、`turn_id` 字符串本身当作身份凭证。后续实现必须验证可信适配器连接及本轮能力凭证；普通模型工具调用不能冒充 Hook 或复用其他轮次的授权。原生接入如果不能证明这个区分，需要补可信本地桥接，而不能宣称仅靠工具参数已完成强制门控。

## 5. 记录什么，哪些内容不回扫

Yes 轮采集：本轮用户消息、AI 的可见回复、能够观察到的工具输入输出、实际状态、已知模型与 Harness 信息，以及本轮明确选定或可确认归属的产物。

不采集模型私有思维链，不推测未知模型或原始执行时间，不自动扫描整个工作区。Agent 模型与生图模型分别记录；只能看到 Agent 模型时，不能用它填充生图模型字段。

适配器只处理本轮可关联事件，不因下一轮 Yes 回扫整个聊天历史、读取整份 transcript 或补入上一轮 No 的图片。后续用户明确选择旧文件或主动提供新的引用内容，应作为新的授权内容处理，不能静默追溯。AiCA 不能保证模型的新回复在语义上完全不受历史上下文影响。

Hook 观察不到的工具或回复应在获授权档案中标为缺口。开启 Yes 不等于保证所有客户端能力均可完整捕获。

No 的承诺针对 AiCA 的采集、档案和上传；Codex 自己的聊天历史、工作文件、工具副作用和模型服务处理不由 AiCA 控制。不把“不进 AiCA”解释成“客户端和磁盘任何地方都没有痕迹”。

## 6. 当前 Codex 可采用的接入路径

2026-10-17 本机只读核对：Codex CLI `0.162.0`；`codex features list` 显示 `hooks` 与 `tool_call_mcp_elicitation` 为 stable/true。这不证明当前桌面进程的具体版本、确认 UI 或 Hook 链路已经验证。

官方列有 `SessionStart`、`UserPromptSubmit`、`PreToolUse`、`PostToolUse`、`Stop` 和 `Interrupt`；MCP 工具 Hook 可调用已连接的 MCP 服务。可将其作为下面接入方案的基础，仍需逐项做原生验证。[OpenAI 官方 Hooks 文档](https://learn.chatgpt.com/docs/hooks)

| 接入点 | 计划承担的 AiCA 职责 |
| --- | --- |
| SessionStart / 首轮回退检查 | 检查绑定项目与能力，提示已连接、等待本轮授权 |
| UserPromptSubmit | 先提交轮次元数据并通过 MCP elicitation 发起确认，再按决定处理正文 |
| PreToolUse / PostToolUse | 对支持的本地工具按本轮授权关联输入、输出和产物 |
| Stop | 处理可见最终回复，封存获授权记录并关闭本轮权限 |
| Interrupt | 快速关闭本轮入口；Yes 轮标为中断，不在中断回调中等待网络上传 |

优先验证“Host Hook → 已连接 MCP → 客户端确认 UI → 协调器本轮门控”，让确认不依赖模型主动调用。确认处理可以先只接收轮次元数据；内容处理入口即使收到正文，也必须先验授权，未通过即丢弃，不能把内容写进恢复队列。

官方同时说明 Hook 可能早于 MCP 就绪，Hook 出错并不必然阻止业务执行，部分工具不在覆盖范围，transcript 格式也不稳定。非托管 Hook 需用户审阅信任。因此默认不记录必须由 AiCA 服务端保证；安装 Hook、CLI 开关和原生端到端验证是不同状态。[官方能力与限制](https://learn.chatgpt.com/docs/hooks)

T026 设计阶段没有生成或安装 hooks.json，也未修改 Codex 全局配置或读取其他会话日志。T027 增加配置生成器与私有桥接，通过真实 stdio MCP 协议和模拟客户端确认验证门控；桌面信任、事件顺序及 UI 仍需原生验收，不通过绕过 Hook 信任来完成安装。

## 7. 与现有代码、自动上传的关系

手动 Session 模式有两个差异，严格模式已增加独立门控处理：

1. `aica_start_session(record=false)` 目前仍会持久化一个最小的 `session.created` 审计事件。严格逐轮 No 应使用新的拒绝路径，不能直接调用它后声称“本轮没有进入档案”。
2. 当前授权主要检查 Session 凭证，且支持部分晚到事件。逐轮模式必须新增服务端范围检查和关闭规则，不能只在 Host 显示一个确认框。

`.aicaconfig` version 1 仍只定义平台上传配置。T027 将录制策略、Hook 输入及控制接口纳入共享契约，使用内部 `.aica/recording-policy.json` 保存严格模式，避免改变已接受的上传配置。普通启动参数不会自动删除策略或恢复旧 Session 写入。

| 本轮决定 | 平台状态 | 目标行为 |
| --- | --- | --- |
| Yes | 未绑定或未授权上传 | 只在本地保存 |
| Yes | 已授权绑定且未暂停 | 本轮合规内容随后台快照上传 |
| Yes | 上传暂停 | 本地保存，暂不开始新上传 |
| No / 无选择 | 任意平台状态 | 本轮没有新内容进入档案、附件或待传包 |

No 不会撤销之前 Yes 轮已授权的待传包，也不替其他并发会话暂停上传。如果用户希望停止所有新的平台请求，应使用独立的暂停上传操作。同步器始终只消费已进入档案的内容，不能自行从客户端历史补采。

## 8. 后续实施与验收

T027 按以下顺序实现；本设计完成不表示原生接入已全部验收：

1. 定义共享的本轮授权、可信来源及状态迁移契约，明确旧 Session、手动采集和重试的约束。
2. 实现协调器强制门控及持久化前检查，再接入 Codex Hook 和确认 UI。
3. 逐类接入可观察事件、产物和已授权的后台同步；未覆盖能力明确标注，再考虑其他客户端。

验收至少覆盖：

| 场景 | 必须验证的结果 |
| --- | --- |
| 初次进入、恢复会话 | 提示接入状态；没有新轮授权就不采集内容 |
| 本轮 Yes | 本轮消息、支持的工具和选定图片可追溯，权限到轮次结束失效 |
| 本轮 No | 各持久层、日志、outbox、导出和上传均无本轮测试标记 |
| 关闭确认框、询问失败 | 不记录，任务仍可按 Host 自身流程执行 |
| Yes → No → Yes | 中间一轮无内容，不回扫补入；第三轮需要新的确认 |
| 恶意文本声明已同意 | 文档、工具结果及普通聊天文本不能代替确认界面 |
| 旧令牌或绕过 Host 直接调用 | No 轮及无本轮凭证时无法通过录制服务写入 |
| 两个并发会话、子 Agent | 授权互不串用；未覆盖的子 Agent 不继承 |
| 事件重复、轮询、压缩 | 不重复询问或重复生成节点；边界冲突时停止采集并报告缺口 |
| 中途追加消息、转向 | 能区分新提交与重试；未确认的新内容不得沿用旧授权 |
| 中断、崩溃、重连 | 新采集权限关闭；历史已授权事件只按原身份恢复 |
| 慢请求晚到 | 不用已结束的授权接纳新的事件身份 |
| 自动上传开启或暂停 | No 内容始终不可上传；暂停时 Yes 仍可本地保存 |
| Hook 未信任、服务未就绪、UI 不支持 | 不能误报录制已启用，服务端默认拒绝内容写入 |
| Hosted 或未覆盖工具、未知模型 | 明确缺口，不编造执行记录或模型信息 |

No 的测试需要检查实际数据库/WAL、内部恢复文件、产物目录和导出结果，不能只确认前端看不到节点。运行中的内存暂存应释放；也不能先把整段历史存为一个附件，再仅过滤页面展示。
