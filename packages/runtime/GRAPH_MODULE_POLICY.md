# 复用优先的创作模块解析

用户最新确认：保留共享意图、人物和风格模块，同时必须逐页保留内容、提示词与可核验图片。模块内新增可选prompts/pages，旧图缺省为空；主格式仍为 `aica-semantic-graph/0.1`，Schema和生成TS同步扩展。此要求取代原先把逐页内容只藏在证据中的展示策略。

## 模块边界

- 先识别具有共同修改范围的创作决策，再归入详细材料和原始调用。贯穿多页的人物/风格优先成为共享模块，相关生成模块引用它，避免复制整段约束。
- 同一分页任务通常归为分镜/画面模块，页号、场景、对白、修订和质检保留在内部材料及原始调用中。独立替换的封面或业务分支可以单列，不能只因工具相同合并无关职责。
- 模块数量按实际职责和页面确定，不再以4至8个作为分页内容的合并目标。不凑数量、不丢失独立修改职责、不编造人物/风格、不删真实依赖；聚合执行DAG和端口仍须校验。
- label用短名称，purpose用一句职责，requirements仅保留少量核心共享约束。详细分镜、对白、Prompt从证据读取，不在核心字段重复全文。

## 规则辅助与模型分工

`reusability.py`对已读取JSON字段及文本寻找意图、人物、风格、逐页内容的候选线索，记录事实引用和少量位置，放入内部prepared input的module_hints。计数不是复用次数，词语命中不是确认语义；模型须回查事实。未读取图片/PDF内容时，不因文件名或存储哈希臆测内容。

每个已接受请求仍最多一次模型调用，不新增模型/embedding依赖或自动重试。parser/prompt升至0.5.0用于追溯策略和拒绝旧审阅快照；最终Graph格式不升级，C不消费内部提示。

## 既定字段的展示

| 层次 | 使用现有字段 |
| --- | --- |
| 默认画布 | label、purpose的一句作用、必要关系及简短候选标记 |
| 模块内容 | purpose、requirements、variables；只显示真实存在的执行参数 |
| 内部材料 | evidence_ids、artifact_ids、source_node_ids、run_ids，按需读取分镜/对白/场景 |
| 追溯与缺口 | evidence、coverage和解析版本，折叠查看，不丢失 |

模块使用prompts与pages保存原始提示词引用、AI整合/建议、逐页摘要和登记图片ID；不新增执行工具枚举或伪造可执行层级。原始提示词由程序从已校验源材料逐字保存，模型只能返回consolidated/suggested，不能伪造recorded。仅有附件的项目仍保持source_node_ids/run_ids/variables为空、executable=false；候选材料步骤不是录制的执行历史。

本地报告默认只显示模块名和短作用，详细约束、材料、参数、执行身份、关系解释及缺口折叠。布局只为阅读计算，语义箭头不等于执行顺序，循环语义关系也须终止布局。可在材料内打开已验证本机图片；无法可靠归属的材料保留在待归属区并提示数量，不按哈希硬绑。

C可按同样分层消费既定字段。实际编辑服务、重跑、缓存、Dirty传播及执行授权不因本次策略而假装已实现。

0.4.0补充通用职责与独立替换检验，不将所有任务套用漫画模块。大文本/JSON材料校验完整哈希后可提供明确标记的首中尾摘录；摘录不证明未展示内容。原材料与证据保留，仍不自动重试模型。

0.5.0提供prompt_catalog/page_catalog给模型，目录正文为有界预览，完整原始提示词保留在后端；超过单材料文本预算的JSON也先提取全部结构化页面和提示词，再压缩模型材料。图片仅依据登记产物、producer或页内容的显式URI/ID引用关联；缺失图片如实标记，不能按哈希或猜测文件名绑定。
